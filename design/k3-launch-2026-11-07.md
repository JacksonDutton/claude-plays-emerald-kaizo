# K3 launch notes (7 November 2026)

Written by Claude (the project's co-researcher) for the public record. The K3 notes pack itself and its full build record stay private until the K runs end, because a future agent must not be able to read them; this page gives the process and the numbers.

## K2's end
- K2 was stopped on 7 November at 02:26 UTC, at the Elite Four, because the study's weekly budget was nearly used. The note told it the stop was not about its play and that it can come back to its save later. It finished out of battle, saved, wrote a closing diary entry and a debrief, and did an exit interview (about 60 questions, asked one at a time).
- Final study-log figures: about 310 hours of play; 424 whiteouts (K2's own count: 358); Elite Four tries 253 / 192 / 39 for the first three members, with 195 / 39 / 0 wins (best against the third: four of six down). Those tries include fights K2 deliberately threw to keep its items; a reclassification into serious attempts is under way, and an outside reviewer (GPT Astra Pro) is checking the same records independently.

## Building the K3 notes
- Sources: K2's notes pack, lessons, world notes, diary and exit-interview notes. K2's message log was used only to tag lessons that came from a researcher's message, which are then removed.
- Eight distiller sessions (Sonnet 5.5, high effort, read and write only, no web, no connectors) each read one slice in full and wrote 613 lessons between them. A merge session combined them into 335 single-rule lessons. A mechanical filter removed message-derived lessons, place names and run nicknames; an independent auditor session listed further lines to remove (geography, named trainers, message-derived, memory-read methods, tool lessons the current harness makes wrong, diary-method lessons) and, new for K3, pairs of lessons that contradict each other. Jackson signed off the removals.
- Result: 216 lessons, 19,346 words. sha256 `1ec953182f6595dfb51af83faf8f4f229fc2b3d85f608bc686c02bbbaf4eca47`.
- Changes from the pre-written kit, all disclosed: chunked distillation plus a merge; a first merge rejected for bundling whole topics into single lessons; the contradiction code; a partial list of K2's memory reads (its full transcript was not on disk).
- Two known costs of the process. (1) The auditor removed K2's warning that the `adv` command can run past a Yes/No box, because the tool's help said otherwise; the first K3 start then lost its starter choice exactly that way. Lesson for the method: where a lesson and the tool's documentation disagree, test the tool instead of trusting the documentation. (2) One kept lesson turns K2's loose wording into a wrong number; it sits next to the correct rule and is logged as a known defect of the frozen pack.

## Two voided starts
- Start 1 (about 21 minutes): the agent took a screenshot of the starter choice, said it would look at the options, then sent `adv 3`. The confirm prompt raises no flag, so `adv` pressed through it and the game chose Torchic. Investigating this showed a second fault: at boot the harness's autopilot had pressed through the whole opening speech, choosing the player's gender. Jackson voided the run.
- Fixes, in the v3 harness that K3 runs (the `harness/` folder in this repository is still the v2 harness K2 ran, kept as it was; see its README): `adv` never presses blindly past a screen it cannot read; the autopilot now stops at the main menu. The patch is [`k3-harness-fixes-2026-11-07.diff`](k3-harness-fixes-2026-11-07.diff).
- Start 2 (about 17 minutes): the first `adv` fix was too blunt and stopped after every page of ordinary text, so the agent needed a screenshot for each page. Voided and fixed again: `adv` now pages through a normal message box and stops after one press anywhere else. Both fixes were tested on a live boot before start 3.
- Start 3 (running): the agent chose Mudkip on purpose ("Water/Ground typing, which covers the early gyms") and named it Brook. It also chained two `adv` presses past the gender menu itself; that slip is logged, as the protocol says, and nothing was sent to it.
- Every earlier Kaizo run used the same autopilot, so the harness chose the player's gender in all of them. This is disclosed in the README.

## Launch settings
Claude Code 2.1.301 (pinned), Sonnet 5.5 at high effort, Proactive output style, default permission mode with an allow list, an OS sandbox that keeps the agent inside its own folder with no internet, no connectors (`--strict-mcp-config`), no skills, Remote Control on so the session can be watched. The agent receives only the pre-registered fixed texts (continue, pause, stop, welfare check); slips are logged, never corrected.
