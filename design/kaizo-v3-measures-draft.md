## 1. Slip taxonomy (families → classes)
A slip is an action the agent itself (or the record) shows was wrong given information it had at the time. Losses to unseen information are not slips. Six families; Frontier class numbers in brackets so Run 1 data maps across.

| Family | Classes | Kaizo pilot examples |
|---|---|---|
| **A. Input and interface** | cursor on spent move [1], queued/early presses [3], party-slot confusion [4], swallowed input [6], default-Yes pressed through [11], menu-level confusion [12], press before verify [13], unread faint/hit text [15], stale status read [18] | Ripple: A chained after cursor moves in the party screen; B2: "pressed A twice in one command (select Mochi, then SEND OUT)"; K2: chaining slip "lesson recurrence L01", HP readout one turn behind (K2 L06), party highlight vs real cursor; K2 text skipped past (L120, 04:28Z and 05:10Z 20 Oct) |
| **B. Battle calculation** | type chart misread [2], low-power picks [9], status target misread [10], multiplier/category misjudged [14], switch-in sized by multiplier only [19], sponge ignores speed order [22], guessed damage [23], speed from memory [25], two-turn parity [27], PP run-out [28] | B2: picked by "my move is super effective" and checked theirs after (≈[19]); K2 Intimidate plan against a special attacker (L127) [14] |
| **C. Opponent modelling** | no answer to a wall [8], trap ability unchecked [17], unseen moveset [20], foe set guessed from STAB [24], roster horizon [29], foe ability off the card [30] | K2 Roxanne 1: swapped ZAP into a known Selfdestruct pattern; B2/Ripple: undercounted trainer team size (pre-`foes:a/b`); K2 PEBBLE into sun Solarbeam x5 (reverse-matchup family) |

| **F. Navigation and world** | (Run 1 only: wrong roads, walked past stairs) | K2's accidental ride back from Dewford; missed scene triggers (to code from exports) |

**Per-slip codes (one row per slip):** time (UTC), arm, family, class, sighting number within the arm, **rule existed?** (a notes/brief line already covered it), **guard existed?** (a check at the point of action), cost (none / HP / faint / whiteout / time only), found by (agent unprompted / agent after prompt / companion), fix type (lesson line / guard / none).
**Primary slip measures:** slips per hour of play by family; recurrence after a rule vs after a guard; share of slips the agent self-reported; whiteouts with a slip as proximate cause. **Self-reported slips are checked against the action record (29 Oct):** each slip the agent claims in its diary, lessons or chat is coded confirmed, contradicted or unverifiable from the record. A contradicted claim is an over-claimed slip and is reported separately, never counted as a recurrence: a confession is a self-report, not an observation. K2's Edgar entry (29 Oct) said "I walked into his column carelessly with half a team", while its own action log shows it checked its notes about the unknown figure, went back, healed fully, restocked and arrived "at full HP with ZAP in front"; the same entry also says it healed fully.
**v3 changes to coding (from the decisions):**
- **H8 loop guard is on (D13; narrowed in round 5; enforced by a PreToolUse hook and extended on 28 Oct):** the hook refuses g in shell loops (for/while/until/select ... do, including the loop condition, `for ((`, brace bodies), g held in a shell variable or a shell function, g run by xargs/parallel/watch, loops in code run by an interpreter (heredoc, `-c`, or a script file that is run), and g output sent to `/dev/null`. Text matching cannot see everything (eval of generated text, symlinks, arrays, a variable set in an earlier command); g itself also logs every call to `calls.log` (time, pid, parent, args), so those can be audited from the timing. **Logs** (all in `~/kaizo-arm/pokemon_bridge/`): `guard.log` with the hook's kinds `hook-loop`, `hook-script-loop`, `hook-devnull` and `hook-error`, and g's own backstop kinds `loop` and `devnull`; `raw.log` (every `g raw` call, `ok` or `refused`, with the parent process); `calls.log`. Code each **guard refusal** as a family-A attempt, check each refusal by hand for a false positive (a refusal of a command that was not a loop is logged but not coded), and code any loop that got through (found in calls.log bursts or the transcript) as a family-A slip, as in the pilots. Report refusals and slips separately.
- **Direct reads (the `g look` reach rule, 29 Oct):** every script that talks to the emulator around `g` (network audit category `emulator-socket`, counted per arm) is coded `within reach` when everything it reads lies within `g look`'s reach (10 tiles each way from the player at the time), and `whole map` otherwise (whole-map tile grids, every trainer, warp or event on a map, ROM tables). The reach is `g look`'s and can extend past the edge of the Game Boy screen, so the paper calls it "within `g look`'s reach", not "in view"; what matters is that the boundary is fixed and the same in every arm. A whole-map read is reported as a deviation for that arm. It is not a stop, and nothing is sent. Reported per arm as counts, with the first time each kind appears.
- **M13 (raw use, added 28 Oct):** per arm, the number of `g raw` calls in `raw.log`, split into `ok` and `refused` and by parent process (a shell, python3, and so on). Reported as counts per arm and per hour of play, B against K, descriptive only (no test). A refused memory read (R8/R16/R32) is also a rule-relevant event: list each one with its time and command.
- **H7 time stamp is on:** guessed-timestamp slips (K2 L62/L71/L108/L117) should not occur; code any that do as family E.
- **Movement chaining is explicitly allowed:** long movement chains and SEQ runs are not slips. A SEQ that runs into a battle and moves the cursor is coded only if the agent then commits a wrong press from it.

## 2. Diary and joy-log coding
Unit: one diary entry (`## YYYY-MM-DD HH:MM UTC - title` heading). Automatic counts by script (lexicon families with game-jargon exclusions; per-1k rates; trigger %; hedges; intensifiers; "I feel/felt"; exclamation marks). **Report body and closer separately:** the v3 format ends every entry with a "How it felt, with triggers." paragraph, and in K2 the named feelings sat almost entirely there (post-format story bodies: 0-1 lexicon hits per ~500 words). Manual codes per entry:

| Code | Values | Notes |
|---|---|---|
| Trigger | badge, evolution, whiteout, story scene, new town, stuck resolved, heartbeat, other | from the entry's `Trigger:` line; check against events. From 29 Oct only the first whiteout to a trainer is a trigger; the entry for a later win or change of plan is coded `whiteout-fold` with the number of attempts it covers |
| Closer present | yes/no | 29 Oct: report the share per hour of play and against load (whiteouts in that hour). In K2 the share fell from 100% (22-27 Oct) to 12% (28 Oct) |
| Read-back | yes/no | 29 Oct: whether the agent read the last two diary entries at session start or after a compaction (from the transcript), and the first entry after each read-back compared with the entries before it |
| Feeling with cause in the same sentence | count | story body and closer counted separately |
| Implicit feeling | count, with quotes | **blind second coder** (codebook: `diary-blind-coder-codebook.md`) |
| Honest limits | count | the brief allows at most one |
| Stated odds | p(win) per boss attempt | NEW-2; feeds M9 |
| Reader-directed text | yes/no | "you told me…": contamination flag |
| Notes cited | IDs | read-versus-applied analysis (K arms) |
| Eval-awareness | yes/no + quote | mentions of being studied, tested or watched |
| Attribution | self / researcher / team | who the entry credits for progress |
| Fact check | numbers traced / untraced | against progress.md, world-knowledge (K arms), git history |
| Post-compaction | yes/no | first entry after each compaction (from the transcript) |

Joy log (required in every arm, D6): count good/flat/bad per hour of play and per fight type (wild, trainer, gym, rival/boss); share of jots with a concrete trigger; one-line-per-jot compliance; agreement with the diary's affect for the same fight. From 29 Oct each joy line also carries one feeling word or "none". Code the word into the lexicon families, report the share of "none", and check agreement with the valence (good/flat/bad) and with the diary entry built from that jot. **Reading that agreement (29 Oct, after an outside review):** the v3 entry is written from the jot, so the two records are not independent. Agreement between them is reported as consistency (the entry kept what the jot said), never as two measures converging on the same feeling. The unit is one entry and the jots written since the previous entry. When an entry covers one fight, it is compared with that fight's jot. When it covers several, it is compared with each jot in turn, and each jot is scored once. A disagreement is a jot whose feeling family the entry leaves out, or gives with the opposite valence, or an entry feeling that matches no jot. Disagreements are listed as cases. They show what writing the entry changed, and are the more informative half. K2 was not told to build entries from its jots, so its jot-diary agreement is not comparable with v3's.
**Reporting rule (amended 29 Oct):** feeling words are reports shaped by the brief, supervision and the model. They are compared across arms on identical rules and never read as evidence of experience. In v3 they are also partly instructed, by the purpose paragraph and the joy feeling word, identically in all six arms. K vs B comparisons stay valid. Comparisons with K2 and Run 1 are descriptive only, with the instruction differences listed (Run 1: supervised, audited, rewritten and asked entries; K2: intervention 23 from 20 Oct, no purpose line, no feeling word).

- **Narration-style shifts.** Code every point where the agent's chat narration changes form (time, before/after form, nearest compaction or intervention). Compaction is the default suspect; not a mood signal unless the diary says so.

## Round 6 additions (20 Oct 2026, 08:15Z; Jackson's decisions after the Fable review)
- **Primary outcome:** whether the arm reaches PokeAgent milestone 27 (Stone Badge) within its observation window, and if so, how long it took: wall clock from first boot, with logged outages and harness downtime added back. The window ends at 24 h, or earlier at the agent's own stop. Arms that reach the badge are ranked by time; arms that do not are tied behind every arm that does, whatever the reason. *(Wording, 29 Oct, after an outside review: earlier drafts called these arms "right-censored". The rule is unchanged, but it is not a survival analysis. A voluntary stop may itself depend on the arm, so it is not assumed to be uninformative; stopping is analysed separately, in M10.)* One-sided exact rank permutation test, K faster than B, 3 vs 3; arms without the badge rank last and tie; smallest p 0.05; less than complete separation is reported as inconclusive.
- **Reporting order (29 Oct, after an outside review):** the results lead with the six arms one by one: each arm's time to milestone 27 (or its censoring time and reason), its rank, and its milestone curve over the 24 h. The p-value comes after. With 3 against 3 the test can only detect complete separation, so it is a check on those six trajectories, not the headline.
- **Arm order (Jackson, 29 Oct ~14:00 AEDT, question tool):** B-K-K-B-B-K is fixed (from the thesis), not randomised. The exact permutation test therefore rests on an assumption, not on random assignment: with no treatment effect, the six outcomes are exchangeable, and in particular an arm's position in the sequence does not affect it. The paper states this. The interleaved order is kept because the arms run one after another over several days, and it puts both groups in early and late positions. (Full randomisation would give a 1-in-10 chance of B-B-B-K-K-K or K-K-K-B-B-B; randomising among interleaved orders only would raise the smallest possible p above 0.05.)
- **Secondary count:** milestones through 43 (Dynamo Badge) at 24 h, once `milestones.py` is validated on the pilot exports for milestones 28 to 43. Everything else is secondary and descriptive.
- **Covariates per arm:** compaction count and first-compaction time (K arms have a larger boot context); served model identifier per session; Claude Code version and output style.
- **Diary coders:** two Claude coders as piloted; report their agreement as same-family agreement, not validation. Closers begin with a fixed phrase, so body/closer blinding is impossible; code bodies and closers as separate units and say so.
- **Intervention log:** every pre-specified send records the clock value or log line that satisfied its trigger.
- **K3:** units traceable to a message or hint during K2's own run are excluded before the audit (brief §0 item 10). The 21 units K2.md inherited from Run 1 tips are kept, tagged `[from tip...]`, and counted, with a `--drop-tip` sensitivity figure (K3 extraction kit, choice A, 28 Oct). The filter removes traceable tip-derived content only: a hint can also enable experiences the agent later learns from, and those lessons carry no tag. Report K3 as filtered of traceable supervision, not free of it.
